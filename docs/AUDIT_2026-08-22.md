### [ ] P0-1 · Phone crash after bundle download in Expo Go (UNRESOLVED)
**Area:** boot path. Expo Go loads `exp://100.71.147.82:8082`, bundle downloads
+ evaluates ("RevenueCat Browser Mode" reaches Metro), then silent death. No JS
error surfaces. The minimal probe app renders fine on the same phone → device,
Expo Go, Tailscale all healthy; it is deckd's code or config.

**Bisect plan (executable):**
1. Re-apply boot instrumentation to `app/_layout.tsx`: ErrorUtils global
   handler logging message + 6 stack frames, plus stage markers
   (module-eval → render-start → assets-ready → navigator-mounted).
   One reload pinpoints the dying line in Metro logs.
2. Stages stop after module-eval → import-time crash. Comment out one at a
   time in `_layout`: useTableSoundBridge (expo-audio), GestureHandlerRootView
   → View, SafeAreaProvider, then Stack.
3. All stages print, then dies → first-route render crash. Mount `index` as
   bare Text to split layout vs HomeLayer.
4. Ranked suspects: expo-audio player init on native, gesture-handler root
   config under new arch, Reanimated worklet init during hidden-layer mounts,
   splash-screen hide timing.
5. Keep `workspace/deckd-probe` until closed.

**Verify:** deal flow works on iPhone over Tailscale; navigator-mounted marker
prints; no silent death.

### [ ] P0-2 · Host authentication is forgeable — secret ships to clients
**Files:** `lib/entitlement.ts:6-16,31-45`, `src/store/lobbyStore.ts:127-153`,
`server/index.js:118-127`.
The client computes the host HMAC from `EXPO_PUBLIC_DECKD_MASTER_SECRET`.
`EXPO_PUBLIC_*` is bundled into the app — anyone who extracts it can mint host
tokens for any clientId and host paid lobbies free. `hostLobby()` also never
checks `hasMasterPass` before sending a token. If the server env var is unset,
the relay accepts every host anyway.

**Fix:** remove the shared secret from the client entirely; authorize hosting
server-side via RevenueCat webhook-backed identity or short-lived server-issued
host grants/JWTs; fail closed at relay startup when production auth is not
configured.
**Verify:** production bundle contains no signing secret (grep the export);
`create_room` with arbitrary tokens fails; missing server config rejects hosts.

### [ ] P0-3 · Host reconnect can be hijacked during grace window
**File:** `server/index.js:129-145`. Host reclaim checks only
`existing.hostGraceUntil > now` against the **room code** — no identity or
resume-token binding. Anyone who learns/guesses the 6-char code during the
30s grace window becomes host.
**Fix:** issue a cryptographically random single-use host resume token on room
create; require it for reclaim; bind to original host identity; invalidate
after use. Room code is an address, never a credential.
**Verify:** e2e test — host drops; second client with only the room code is
rejected; original host with resume token reclaims once; token reuse fails.

## P1 — Wrong behavior / robustness / visible perf

### Multiplayer & relay
- [ ] **P1-1 · Duplicate clientId overwrites live sockets**
  `server/index.js:180-205,141`. `room.clients.set(ws.clientId, ws)` without a
  presence check; old socket's close handler deletes the replacement's entry
  → ghost connections. Fix: reject duplicates or close old first; close
  handlers delete only if `room.clients.get(id) === ws`; prefer server-issued
  connection nonces. Verify: join twice with same ID, roster stays correct.
- [ ] **P1-2 · No ws payload cap or rate limiting**
  `server/index.js:90,99-110,226-243`. No `maxPayload` on the ws server;
  relay fans arbitrary strings to every member; per-relay activity refresh
  lets a client keep rooms alive forever. Fix: explicit maxPayload sized for
  event batches, token-bucket limits per socket + room, backpressure handling,
  IP-level join throttling (Cloudflare). Verify: oversize payload closes
  socket; flood gets throttled; normal batches pass.
- [ ] **P1-3 · No protocol version check or runtime schema validation**
  `lib/relayProtocol.ts:9,51-58`, `server/index.js:99-112`, transport casts
  payloads without validation. `RELAY_PROTOCOL_VERSION` declared but never
  sent. Fix: version every wire message + reject unsupported; runtime-validate
  every message kind (event batches, intents, sizes, sequence bounds);
  structured protocol errors instead of silent drops. Verify: skew/malformed/
  oversized fixtures get deterministic errors, no state mutation.
- [ ] **P1-4 · Snapshot request floods all guests, no request binding**
  `lib/relayTransport.ts:308-312`, `multiplayerBridge.ts:243-274`. One guest's
  `request_snapshot` makes host send full chains to EVERY guest; no request
  IDs. Fix: respond only to requester; add request IDs + rate limit.
  Verify: A requests, B receives nothing.
- [ ] **P1-5 · No ACKs, gap detection, or retry — silent divergence**
  `relayTransport.ts:280-312`, `syncLogic.ts:186-211`. Sends resolve on
  `ws.send()` regardless of delivery; a dropped batch leaves a guest divergent
  forever. Fix: batch IDs + highest-contiguous-seq ACKs, bounded retries, gap
  detection triggers targeted snapshot. Verify: drop one batch in a test
  transport → guest detects gap, recovers via snapshot.
- [ ] **P1-6 · Send silently no-ops when disconnected**
  `relayTransport.ts:280-299`. Unconditional resolve = false success during
  reconnects. Fix: reject when not open, bounded queueing, connection
  generation tracking. Verify: sendEvents while closing rejects.
- [ ] **P1-7 · Guest intent validation relies on unsafe casts**
  `multiplayerBridge.ts:172-230`. `(payload ?? {}) as {...}` and action-string
  casts reach the engine. Fix: intent allowlist, field-level validation,
  reject unknown actions pre-engine, intent rate limits + dedup IDs.
  Verify: fuzz each intent with null/nested/huge/unknown values — no throw, no
  state change.

### Engine & persistence
- [ ] **P1-8 · Snapshot restore discards event-log baseline**
  `gameStore.ts:294-300`, `syncLogic.ts:233-243`. Guest keeps only
  `appliedTail` after a snapshot; later `ingestRemoteEvents` folds from
  `emptyState()` over the tail → lost baseline, rejected events, divergent
  state. Fix: retain baseState/baseSeq checkpoint semantics or keep the
  canonical chain. Verify: snapshot → ingest next event → state matches host.
- [ ] **P1-9 · `canApplyEvent` accepts everything unknown**
  `engine/state.ts:154-181`. `default: return true`; no phase/actor/card
  validation in the reducer — remote/replayed events can mutate invalid state.
  Fix: explicit admissibility per event type; enforce session identity +
  contiguous seq at sync boundaries. Verify: negative tests (wrong actor
  turn/end, non-current bet, card/move cross-zone, dup/out-of-order seq).
- [ ] **P1-10 · `hand/reorder` can silently delete cards**
  `engine/state.ts:164-169,314-320`. Partial order arrays pass validation and
  permanently drop other cards from the hand zone. Fix: require equal length +
  set equality + uniqueness before applying. Verify:
  `canApplyEvent(state, partialReorder) === false`.
- [ ] **P1-11 · Poker reducer accepts illegal bets**
  `engine/state.ts:376-409`. Bets clamp instead of validating: fold-then-bet,
  non-current bettor, under-min-raise all apply. Fix: one canonical pure
  betting validator shared by rules.apply and canApplyEvent; reject, don't
  clamp. Verify: property tests across the invalid-bet matrix.
- [ ] **P1-12 · Silent volatile-storage fallback loses data invisibly**
  `lib/storage.ts:33-52`. Any MMKV failure swaps in a process Map; writes
  appear to succeed, everything evaporates on restart. Fix: distinguish
  intentional Expo Go fallback from failure; persistence-health flag; surface
  session-only warning; don't swallow write errors. Verify: mock createMMKV
  throwing → stores report persistence-disabled rather than fake-saving.
- [ ] **P1-13 · Persisted stores lack migrations**
  `gameStore.ts:523-533`, `presetsStore.ts:72-88`, `sessionHistoryStore.ts:37-42`,
  uiStore. `version: 1`, no migrate (only profileStore has one). Old JSON
  hydrates unvalidated; gameStore folds stale event schemas into garbage.
  Fix: per-store schema validation + migrate-or-quarantine, esp. gameStore
  events. Verify: v0 fixtures hydrate cleanly under current code.

### UI performance
- [ ] **P1-14 · Every layer stays mounted and subscribed while hidden**
  `app/index.tsx:113-142`. Home/Hub/Table/Lobby/Pass all render unconditionally
  behind opacity; hidden layers run hooks, subscribe, and re-render on every
  store change. Fix: mount current (+ transition adjacent) surface only.
  Verify: Profiler — hidden layers show zero commits during table drag.
- [ ] **P1-15 · TableLayer subscribes to entire state + events array**
  `TableLayer.tsx:301-312`. Any event = full 2183-line rerender + all selector
  recomputation. Fix: narrow selectors (phase, currentPlayerId, shallow hand
  IDs), memoized regions (TableHeader/OpponentRail/TableMiddle/Hand/RuleActionBar).
  Verify: render counters — drag doesn't rerender header/opponent rail/chrome.
- [ ] **P1-16 · Per-card × per-target highlight trees multiply animated nodes**
  `CardDrag.tsx:45-79,178-181`. Every draggable card renders every target's
  TargetHighlight with its own useAnimatedStyle — 10 cards × 4 targets = 40
  nodes. Fix: one table-level DropTargetOverlay driven by the active-target
  shared value; highlights only for lifted card. Verify: overlay count constant
  regardless of card/target count.
- [ ] **P1-17 · Full-hand measureInWindow on every scroll frame**
  `CardDragHand.tsx:61-85,95-121`. Measures every card + slot repeatedly;
  autoplay effect depends on unstable array identities so remeasures on
  ordinary updates. Fix: derive geometry from index/overlap; stable
  cardOrderKey dependency; imperative/shared-value geometry.
  Verify: profile 20-card scroll — no continuous measurement at 60Hz.
- [ ] **P1-18 · Gesture objects rebuilt on every geometry identity change**
  `useCardDrag.ts:104-224`. Pan gesture deps include cardSize/dropTargets/slot
  object props → rebuilt each parent render. Fix: primitive geometry, memoized
  targets at table level, shared values for changing geometry.
  Verify: no gesture recreation churn during scroll frames.
- [ ] **P1-19 · Inline style identities defeat PlayingCard memo**
  `CardDragHand.tsx:163-216`, `TableLayer.tsx:1028-1145`, HubLayer list rows.
  New object literals per render defeat React.memo on PlayingCard.tsx:79.
  Fix: memoized HandCard wrapper, styles computed from primitives inside child.
  Verify: Profiler shows unchanged cards skipped during one-card drag.
- [ ] **P1-20 · Fixed nav chrome squeezes small phones**
  `GlobalNavBar.tsx:437-488` (122px slot, 112-118px hit areas), hand reserve
  142px. On SE-class 667px viewports actions collide with nav. Fix: responsive
  heights via useWindowDimensions compact breakpoint (<720). Verify: 375×667
  + 375×812 across presets — CTAs visible, ≥44×44 hit targets.

## Privacy model note (documented, no fix required)

Privacy filter is directionally sound (placeholders for hidden IDs, rngSeed
stripped, identify-on-reveal only, broadcasts filtered). But it trusts the
host — the relay is a dumb pipe, so a malicious host CAN send unfiltered
events. Document as **honest-host privacy**, revisit if guests ever pay.
