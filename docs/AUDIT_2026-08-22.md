## P0 — Ship blockers

### [~] P0-1 · Phone crash after bundle download in Expo Go (ROOT CAUSE CANDIDATE FIXED, DEVICE CONFIRMATION PENDING)
- Forensic pass (delegated read-only audit) ranked `lib/revenuecat.ts:3` module-scope
  `import Purchases from 'react-native-purchases'` as hypothesis #1: Expo Go lacks
  the native module, and module evaluation happens BEFORE any try/catch can help.
- **Fixed:** `lib/revenuecat.ts` rewritten to a guarded lazy `require()` inside
  `configureRevenueCat()`; `requirePurchases()` added for configured flows;
  `_layout.tsx` no longer imports the symbol. A missing native module can no
  longer take down boot. Commit `d07300c`.
- Temporary BOOT console diagnostics added then removed (`8b09717`) — source
  hygiene restored (0 stray console.log).
- **REMAINING:** reload Deckd on the physical iPhone from the PM2 dev server and
  confirm it boots. If it still fails, next bisect steps are sound bridge →
  multiplayer bridge install (both now isolated by the same lazy pattern).

### [x] P0-2 · Host authentication forgeable → client now fails closed
- Client-side secret/token minting REMOVED (`lib/entitlement.ts`); public env
  vars ignored; entitlement tests assert fail-closed behaviour.
- Server requires `MASTER_TOKEN_SECRET`; `ALLOW_UNAUTHENTICATED_HOSTS=true` is a
  local-test-only escape hatch (never deploy with it set).
- **Known limitation (accepted for v1):** production host grants need the
  RevenueCat webhook path. Until then, production hosting stays unavailable
  rather than insecure. Products/keys remain a Josh task (docs/MONETIZATION.md).

### [x] P0-3 · Host reclaim hijack during grace window
- Server issues a cryptographically random single-use resume token on room
  create; reclaim during grace REQUIRES it; bound to original host identity;
  rotated after use; room code is an address, not a credential.
- E2E verified (`server/reconnect.e2e.test.js`, 8 PASS lines): room code alone
  rejected; valid token works once; reuse fails.
